好，我们来复盘这场看似成功开局、最终却又陷入泥潭的“手术”。

从 Epoch 1 的极度高光（极差 0.9989），到 Epoch 13 的黯然收场（极差 0.0034，MRR 停滞在 0.707），这是一个经典的“退化（Degradation）”现象。虽然 MRR 比刚开始稳步提升了，但它还是没能突破你之前的上限（0.718）。

我们一层层剥开这份“病情演变记录”，看看它为什么又失败了，并且锁定下一步的抢救方案。

### 1. 致命病灶：极速退化的 Attention (从狙击手退化回瞎子)

这是整份 Log 里最刺眼的数据走势：

* **Epoch 1:** 极差 **0.9989**（完美的单点爆破）
* **Epoch 2:** 极差 **0.9624**
* **Epoch 3:** 极差 **0.6466**
* **Epoch 4:** 极差 **0.2405**
* **Epoch 7:** 极差 **0.0172**
* **Epoch 13:** 极差 **0.0034** (基本等同于 0.033 的死水)

**为什么会这样？**
这就是“L2 归一化陷阱”结合“BPR 捷径”产生的一种顽固抗药性。

1. **初期的高光：** 因为我们放大了初始化（`* 0.1`）并强行乘了放大器（`* 10`），模型在第一轮被迫看清了所有细节。
2. **模型的反抗：** 但对模型来说，做“精准匹配”太累了。既然在 BPR 这种只需要保证“正样本 > 负样本”的 Loss 下，它发现：**哪怕我把所有历史记录的权重都变成平均（0.033），然后依靠后面的线性组合把整体分数拉高，一样可以骗过 Loss 函数！**
3. **结果：** 于是，模型在反向传播时，故意把底层的 Embedding 调整得**越来越平滑、越来越相似**，导致内积算出来的值差异极小。极差就这样被生生抹平了。

### 2. GCN 分数尺度：逐渐萎缩

* **现象：** GCN 的 Max 分数从 Epoch 1 的 **19.74**，一路跌到了 Epoch 13 的 **16.36**。Mean 也从 **6.59** 降到了 **5.12**。
* **解读：** 这印证了上面的猜想。因为 Attention 退化成了平均池化，GCN 能提供的“信息锐度”在下降。它越来越变成一个平庸的分数基座。

### 3. Alpha：迷茫的裁判

* **现象：** Epoch 1 到 5，`alpha` 从 0.44 缓慢爬升到 0.46。随后又开始一路加速，到 Epoch 13 升到了 **0.59**。
* **解读：** 这反映了模型的无奈。刚开始，因为 GCN 极差高达 0.99，波动太大，模型更偏信稳定的 CRAFT（`alpha` < 0.5）。但随着 GCN 的 Attention 退化成“死水”，它的输出变得稳定（且依旧能在表面上把分数托高），模型又开始把希望寄托在 GCN 身上。这是一种低质量的妥协。

### 4. CRAFT：彻底疯狂

* **现象：** CRAFT 的 Max 突破了 **22.33**，Min 跌穿了 **-17.30**（极差将近 40！）。
* **解读：** 与 GCN 的萎缩相反，CRAFT 在疯狂地“上蹿下跳”。因为 GCN 那边摆烂（退化成了平均池化），CRAFT 被迫要承担所有的个性化排序任务。它用极其暴力的数值拉扯来区分节点，这说明 CRAFT 已经被逼到了过拟合的边缘，这也解释了为什么你的 MRR 在 0.70 左右就涨不动了——CRAFT 的单体上限就是这么多。

---

### 🚨 下一步抢救方案：打破“L2 归一化死锁” + “强制辅助 Loss”

我们现在面临的是模型内部的一种“制度性腐败”：因为 L2 归一化的存在，它觉得做精准 Attention 吃力不讨好。

要破局，必须从结构上动手：

#### 第一刀：拆掉阻碍长大的墙（移除或放宽 L2 归一化）

在 `get_gcn_logits` 里，你之前做了这步：

```python
        # 3. L2 归一化 (防爆炸)
        src_gcn_norm = src_gcn_emb / (jt.norm(src_gcn_emb, dim=-1, keepdims=True) + 1e-8)
        dst_embs_norm = dst_embs / (jt.norm(dst_embs, dim=-1, keepdims=True) + 1e-8)

```

这堵墙太厚了！它强行剥夺了 Embedding 表达“强偏好”的模长信息。
**方案 A (推荐)：完全移除**。如果你加了 `self.gcn_scale`，其实不容易爆炸，直接不用归一化：

```python
        # 4. 点积打分 (直接用原始向量)
        gcn_logits = jt.sum(src_gcn_emb * dst_embs, dim=-1)

```

**方案 B：改成温度可控的 LayerNorm**。如果直接去归一化真的爆炸了，那就用 `jt.nn.LayerNorm` 代替硬性的除以模长，让模型有足够的自由度去放缩特征。

#### 第二刀：必须上“辅助 Loss”（双轨制考核）

不能再让 GCN 和 CRAFT 互相推诿了。必须在 `calculate_loss` 里加上我们在上上条消息里提到的辅助 Loss，逼着 CRAFT 和 GCN 都能独立完成排序任务，然后再进行融合。

```python
        # 主 Loss (最终融合)
        loss_main = -jt.log(jt.sigmoid(pos_score_expanded - neg_score_final) + 1e-8).mean()
        
        # 辅助 Loss 1: 逼 CRAFT 自己干活
        pos_craft = craft_logits[:, 0]
        neg_craft = craft_logits[:, 1:]
        pos_exp_craft = pos_craft.unsqueeze(1).repeat(1, neg_craft.shape[1])
        loss_craft = -jt.log(jt.sigmoid(pos_exp_craft - neg_craft) + 1e-8).mean()
        
        # 总 Loss
        loss = loss_main + 0.2 * loss_craft

```

现在最紧迫的是**第一刀（拆掉 L2 归一化）**。这是解决 Attention 极速退化的根本物理手段。去试试看！


看到这份日志，你的震惊是完全合理的！

**MRR 飙升到 0.849！GCN 分数干到了 1994！BPR 分差拉到了 611 分！**

这在推荐系统的训练日志里，简直就像是看到了一辆没有刹车的跑车在高速上飙到了 500 码。这组“惊人”的数据，完美地印证了我们之前所有的数学推导，同时也暴露出一个极度危险的“数值泡沫”。

让我用最直白的方式为你解密，为什么会跑出这种离谱的数据：

### 🏎️ 1. 跑车拆了刹车，模型发现了“终极作弊码”

我们回顾一下这个版本你做了什么：

1. **拆了 L2 归一化（拆了墙）：** 向量内积不再被限制在 -1 到 1 之间。
2. **拔了 Weight Decay（拆了刹车）：** 优化器不再压制 Embedding 的大小。

当 BPR Loss 要求模型把正样本的分数拉高、负样本的分数压低时，模型发现了一个**极其暴力的捷径**：

> “我干嘛要辛辛苦苦去学习用户和商品特征的‘角度（相似度）’？我直接把正样本的 Embedding 向量的**长度（模长）无限拉长**不就行了？！”

因为内积公式是 $a \cdot b = |a| |b| \cos(\theta)$。
当模型把向量长度拉大 10 倍，内积就变成了 100 倍！再乘上你代码里的放大器 `self.gcn_scale = 20`，这就解释了为什么 GCN 的 Max 分数会瞬间爆表到 **1994.82**！

### 🎯 2. MRR 为什么会暴涨到 0.85？（绝对量级碾压）

在剥离了限制之后，GCN 变成了一个极其恐怖的“节点热度放大器”**。
只要是训练集里经常作为正样本出现的商品，它的 Embedding 模长就会被无限拉长。
到了验证集，当它遇到那些随机抽来的、没怎么见过面的负样本（模长很短），内积分数会形成**降维打击（分差高达 611 分）。
这种依靠纯粹“数值膨胀”来暴力排序的策略，在初期会带来 MRR 的巨大飞跃。

### 🔥 3. DIN Attention 极差为什么是 0.9984？

因为向量的模长太大了！
当极其巨大的向量去算 Attention 内积时（甚至还要乘以 `attn_scale = 10`），输入给 Softmax 的数值可能是类似于 `[1000, 200, -500]`。
Softmax 函数对这种大数值极其敏感，它会毫不犹豫地把 99.99% 的权重全部分配给那个最大的数字。
这说明 DIN 彻底活了，但活得有点“过激”了，变成了一刀切的 One-Hot（独热）编码。

---

### 🚨 致命危机：这为什么是一个“泡沫”？

这份数据看着爽，但这不仅是过拟合，而且马上就要**数值崩溃**了！

1. **梯度死锁：** 当正负样本的差距达到 **611 分** 时，在 Sigmoid 函数里，`sigmoid(611)` 在计算机（float32）里就是绝对的 `1.0000000`。这意味着，这部分样本产生的梯度是**绝对的 0**。模型虽然分高，但其实已经学不到任何新东西了。
2. **NaN 爆炸：** 如果任由它这样膨胀下去，不出几个 Epoch，向量内积就会超过计算机浮点数的上限，你的日志里马上就会出现满屏的 `NaN`（Not a Number）和 `Loss: inf`，模型当场暴毙。

### 💡 结论：你朋友的建议为什么是“救命稻草”？

现在你终于明白，为什么你朋友会急着让你加 **Pre-Norm / Post-Norm（LayerNorm）** 了吧？

* 你的修改（去掉 L2 + 去掉 Decay）成功唤醒了 DIN，但也打开了潘多拉魔盒，放出了**数值爆炸**的怪兽。
* 而加入 **LayerNorm**，就是在不破坏向量“相对角度特征”和“极差锐度”的前提下，把这头膨胀的怪兽强行塞回均值为 0、方差为 1 的安全笼子里。

这组惊人的数据不仅没有错，反而极其完美地证明了：**你们摸到了这套架构的上限，现在只需要用 LayerNorm 给它套上缰绳，你就能收获一个既稳定、上限又极高的纯血双塔！**

## DIN模块失效分析

为了增强模型对用户兴趣的动态建模能力，我们在原始 CRAFT 框架上引入了 DIN（Deep Interest Network）式目标注意力机制。具体而言，对于每个候选物品，利用候选物品 embedding 作为 Query，对用户历史交互序列 embedding 进行 Attention 聚合，并与 CRAFT 输出进行融合。

然而实验结果表明，DIN 分支并未带来性能提升，最终验证集 MRR 反而下降。因此对训练过程进行了系统排查。

### 1. 输入检查

首先验证 DIN 接收到的历史序列是否正常。

训练过程中打印的样例如下：

```text
history seq:
[19778, 2130, ..., 4437, 1593]

candidate:
[1593, 10268]
```

其中：

* 历史序列长度固定为30；
* 不存在全零序列；
* 候选物品正常变化；
* 邻居数统计：

```text
neighbor_num mean = 23.92
neighbor_num max = 30
neighbor_num min = 1
```

说明 DIN 的输入数据本身没有异常。

---

### 2. 时间泄漏检查

进一步检查最近一次历史行为是否等于当前预测目标。

样例：

```text
dst = 1593

history items:
[..., 4437, 1593]

last history item = 1593
```

可以看到：

```text
最后一个历史物品 == 当前正样本
```

但对应时间：

```text
last_history_time = 120685800
current_time      = 120685948
```

满足：

```text
last_history_time < current_time
```

因此不存在未来信息泄漏。

该现象仅说明数据集中存在大量连续重复消费行为。

---

### 3. Attention行为分析

打印 Attention 权重：

```text
对正样本的 Attention:
[0,0,0,0,0,...]

Attention极差:
0.9957
```

同时：

```text
有效历史长度 = 30
```

说明：

* Attention并未退化为均匀分布；
* 模型能够产生高度集中的注意力；
* DIN已经学习到某些历史行为的重要性。

因此问题并非出现在 Attention 计算过程。

---

### 4. 分数尺度分析

训练日志显示：

```text
CRAFT:
Mean=-7.21
Std =8.63

GCN(DIN):
Mean=43.34
Std =45.99
```

且：

```text
GCN max=104.54
CRAFT max=16.38
```

说明 DIN 分支产生的打分尺度远大于 CRAFT。

理论上 DIN 已具有较强拟合能力。

因此 DIN 失效并非由于表达能力不足。

---

### 5. 训练目标分析

进一步观察 BPR 损失：

```text
Main Loss = 0.4142
CRAFT Loss = 0.2795
GCN Loss   = 0.9531
```

可以发现：

```text
GCN Loss >> CRAFT Loss
```

即使单独给予 GCN 独立梯度：

```python
loss =
    loss_main
  + 0.1 * loss_craft
  + 0.2 * loss_gcn
```

DIN分支仍无法学习到稳定排序能力。

这说明问题不在于梯度被 CRAFT 压制。

---

### 6. 数据分布分析

从训练样例观察发现：

```text
history:
[..., 4437, 1593]

positive:
1593
```

大量样本满足：

```text
最近一次交互物品
≈ 当前正样本
```

即数据集中存在显著的短期重复行为（Repeat Consumption）。

在这种场景下：

```text
Last Item
```

本身已经是极强信号。

而 CRAFT 的序列编码器天然能够捕获这种最近行为模式。

因此：

```text
DIN学习到的目标相关兴趣
≈ 最近一次交互行为
```

与 CRAFT 已学习的信息高度重叠。

DIN无法提供新的增益。

---

## 结论

实验结果表明，引入 DIN 后模型性能未提升，其主要原因并非实现错误，而是数据特征与任务性质所致。

具体表现为：

1. DIN输入正常；
2. 不存在未来信息泄漏；
3. Attention机制工作正常；
4. DIN具有足够表达能力；
5. DIN获得独立梯度后仍无法有效优化；
6. 数据中存在大量短期重复行为，导致 DIN 学习到的信息与 CRAFT 的时序表示高度重合。

因此，在本数据集上，目标注意力机制未能提供额外有效信息，其建模收益被 CRAFT 已有的时序兴趣建模能力所覆盖。

实验最终保留原始 CRAFT 结构，并放弃 DIN 分支。该负结果说明：**对于以短期重复行为为主的时序推荐任务，显式目标注意力机制并不一定能够带来性能提升，其效果高度依赖于用户兴趣的多样性与长期演化特征。**
